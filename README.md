# 微软拼音词库备份 / Windows Pinyin Lexicon Backup

备份 Windows 微软拼音的个人词库，并在你确认后从备份恢复。

Local backup and on-demand restore for the Microsoft Pinyin personal lexicon on Windows. Optional logon checks run silently and exit; the settings window does not need to stay open.

管理窗口用于查看状态、修改设置和手动操作。启用登录自动检查后，即使没有打开管理窗口，程序也会在登录 Windows 后检查一次，必要时备份，然后退出。正常检查和正常自动备份没有窗口、黑框或托盘图标；发现错误或疑似词库异常时才提示。

想了解文件用途、运行关系、修改功能应看哪里，请阅读 [项目导览](项目导览.md)。

## 使用条件与放置位置

- 适用于 Windows 微软拼音，依赖 Windows PowerShell 5.1 和系统的 .NET 桌面组件。当前没有 macOS、Linux 或其他输入法的实现。
- 保留完整程序目录及其中的 src/ 结构，双击 open-gui.exe 打开管理窗口。三个 EXE 都依赖随附脚本，不能单独拿出来使用。
- 将程序放在当前用户可以读写、准备长期保留的目录。是否需要管理员权限取决于文件夹权限，不取决于是不是 C 盘；程序按普通用户权限运行，不自动提权。
- 启用登录自动检查后，计划任务会记录程序的位置。移动或删除目录会影响自动检查；迁移时应先关闭原位置的登录自动检查，在新位置重新启用并确认实际任务状态。
- 当前 EXE 未做数字签名，Windows 可能显示未知发布者或信誉提示。此类提示与文件访问权限错误需要分别排查。

## 第一次使用

1. 双击 open-gui.exe，查看顶部的词库状态。
2. 点击「设置…」，确认备份位置、备份间隔和保留份数。
3. 需要登录后自动检查时，勾选「登录 Windows 后自动检查并按需备份」。默认未启用。
4. 点击「保存并应用」，查看结果，再确认主窗口显示的登录任务实际状态。
5. 点击「立即备份」，确认出现成功记录，并通过「打开备份文件夹」检查存档位置。

关闭管理窗口会退出界面进程。已启用的登录自动检查由 Windows 计划任务独立启动，不依赖窗口保持打开。

## 设置如何生效

| 设置 | 默认值 | 含义 |
| --- | --- | --- |
| 备份间隔 | 7 天 | 登录检查时，距最近普通备份达到该间隔才尝试自动备份 |
| 保留份数 | 30 份 | 自动与手动普通备份合计的保留数量；降低时可能需要确认清理旧备份 |
| 备份位置 | 程序目录内的 snapshots/ | 支持修改；改位置不会自动搬迁旧存档 |
| 登录自动检查 | 关闭 | 启用后为当前用户注册本应用的登录计划任务 |
| 登录后检查延迟 | 20 秒 | 位于高级设置，由 Windows 计划任务负责延迟启动 |
| 相同内容跳过自动备份 | 开启 | 词库内容与最近备份相同时跳过，手动备份不受影响 |
| 日志上限 | 5 MB | 位于高级设置，限制运行日志大小 |

编辑框中的修改先作为草稿，点击「保存并应用」后才写入配置。正在执行的操作继续使用开始时读取的设置，新设置从下一次操作起使用。有未保存修改时，取消或关闭设置窗口会询问如何处理。

配置保存和系统任务变更可能分别成功或失败。出现「已保存，但部分操作未完成」时，应查看具体提示和任务实际状态，不能只凭勾选框判断自动检查已经启用。

登录自动检查只在登录时运行一次，不是每隔几天自行唤醒，也不会持续监控。备份间隔表示每次检查时如何判断到期；到期后仍需等下一次登录检查，或主动手动备份。

## 日常操作

| 想做什么 | 操作 |
| --- | --- |
| 查看词库、最近操作、备份位置和任务状态 | 打开管理窗口；需要更新显示时点击「刷新」 |
| 手动备份 | 点击「立即备份」，或双击 run-backup.cmd；不受备份间隔和内容去重限制 |
| 找到备份文件 | 点击「打开备份文件夹」 |
| 恢复一份备份 | 选中来源为「自动」或「手动」的具体存档，点击「恢复选中存档…」，核对说明后确认 |
| 主动清空词库前暂停自动检查 | 点击「挂起值守」；处理完成后点击「恢复值守」 |
| 关闭登录自动检查 | 在设置中取消勾选并保存，确认主窗口的任务实际状态 |

界面中的词组数量是估算值，用于辅助判断异常，不是准确的词条统计。没有可比较的备份或暂时无法判断健康时，自动检查可能只记录日志并跳过；可通过手动备份建立自己的第一份存档。

## 恢复会做什么

1. 检查所选存档的完整性。
2. 将当前词库数据复制到程序目录内的 quarantine/，校验保全副本后才继续。
3. 短暂停止相关输入法进程，复制所选备份，并逐文件核对内容。
4. 覆盖或核对失败时尝试从保全副本回退；回退也失败时单独报告并保留现场。

取消确认不会执行恢复。恢复期间输入法可能短暂中断；未恢复工作时可注销后重新登录。存档记录最多展示十份，普通备份优先按目录时间戳从新到旧排列，其后才是其他记录。「恢复产物（不可恢复）」不能作为恢复来源，也不计入普通备份的保留份数。

备份先写入临时目录，校验后才成为正式存档。恢复前保全、失败回退和错误提示都是内置保护；出现失败时应保留备份、日志和保全数据，按提示处理。

输入法只在当前会话内处理，按原运行状态尝试重启。重启失败会在结果中单独显示，并在日志中记录程序路径与原因，不会把已完成的数据恢复报告为失败。

命令行恢复使用系统自带的 Windows PowerShell 5.1。先进入程序目录，再运行（替换为完整存档名）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\pinyin-restore.ps1 "2026-10-18_120000"
```

路径或参数含空格时用引号包住整个值，例如 `-File "E:\My Tools\PinyinBackup\pinyin-restore.ps1"`。只有输入 `y` 或 `Y` 才恢复；其他输入取消。人工排查步骤见「排查指南.txt」，提示不会自动证明词库变化的原因。

## 文件与数据存在哪里

| 内容 | 默认位置 |
| --- | --- |
| 本机实际设置 | 程序目录内的 config.json，首次成功保存设置时生成 |
| 普通备份与恢复产物 | 程序目录内的 snapshots/；可以在设置中改备份位置 |
| 恢复前保全数据 | 程序目录内的 quarantine/ |
| 运行记录 | 程序目录内的 pinyin-backup.log |
| 挂起标记 | 程序目录内的 suspend.tag |
| 窗口临时缓存与启动日志 | 优先位于 %LOCALAPPDATA%\PinyinLexiconBackup\instances\〔目录标识〕\temp |

临时目录不可写时，启动器依次尝试程序目录内的 .pinyin-gui-temp/ 和 %TEMP%\PinyinLexiconBackup\〔目录标识〕。这些位置用于窗口运行缓存，不是词库备份位置；程序不会更改系统的 TEMP 设置或自动提升权限。

个人词库、备份、日志、本机配置和运行状态不应上传 GitHub，也不应打进供其他用户下载的程序包。

## 移除界面与完整卸载

双击 uninstall.exe，或点击管理窗口中的「卸载…」。卸载窗口会列出处理范围，执行前再次确认。

| 选项 | 删除什么 | 保留什么 |
| --- | --- | --- |
| 仅移除管理界面 | GUI 入口和界面专用脚本 | 自动检查组件、配置、数据、现有任务、命令行入口和独立卸载入口 |
| 完整卸载 | 属于当前安装的登录任务、清单内程序文件、配置、日志、可识别备份和保全数据、本安装独占缓存 | 真实输入法词库、其他安装的任务、无法确认归属的文件与历史共用缓存 |

仅移除界面不会替你启用自动检查；任务原来未启用或已挂起，处理后仍保持该状态。需要继续自动备份时，保留整个剩余目录；以后可通过留下的 uninstall.exe 完整卸载，也可重新放回完整程序文件恢复界面，并保留已有配置与数据。

完整卸载会删除清单中的备份与保全数据，执行前请认真核对。任务查询、移除或文件删除失败时会报告结果，可能需要处理权限或重新补齐程序后重试。旧脚本的 PinyinLexiconBackup 任务不属于本版本的 PinyinLexiconBackupLogin 任务，不会被本版本卸载流程移除。

## 遇到问题

- **词库不存在、无法读取或无法解析**：先看主窗口及弹窗的具体路径和原因。不要直接覆盖原词库，也不要仅凭「读取失败」认定是文件被占用。
- **备份失败**：检查程序目录与备份目录是否可写、空间是否充足，查看运行日志中的失败说明。
- **设置保存成功但自动检查没启用**：查看任务实际状态和注册失败说明，处理后重新保存设置。
- **窗口启动失败**：保留错误信息。选中的临时目录内有 launcher.log；GUI 崩溃可能生成 pinyin-gui-crash.log，自动检查崩溃可能生成其子目录 PinyinLexiconBackup/auto-check-crash.log。
- **恢复或回退失败**：保留存档、quarantine/ 和日志，按结果处理，避免反复尝试覆盖。

反馈问题时提供操作步骤、预期结果和实际错误。日志或截图可能包含个人路径和词库信息，分享前先检查并隐去私人内容。
